Runic::GameplayAPI is the umbrella target of the GameplayAPI group: it links Gameplay, Combat, GameplayFlow and Quest so the Game links one name, while each module keeps its own boundary and tests.

Godot never reads Physics or the simulation: the client builds a list of what to show each frame (render extraction) and GodotBridge hands it to Godot. Physics [[Debug drawing|debug drawing]] works the same way: Physics fills plain debug-geometry buffers defined in Core, and a GodotBridge debug layer draws them, so neither module links the other. Collision shapes and render meshes are different data.
