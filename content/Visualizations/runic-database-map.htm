How C++ and Go reach the database

The GameServer never opens a database connection. The simulation writes durable operations into the Engine's service port; the Platform's C++ bridge sends them to Go services over gRPC or NATS; only Go services hold PostgreSQL connections, each to its own schema.

The C++ touch points

PieceWhereWhat it does
SimulationPortRunicEngine · Runic::Simulation (SIM-5), header-only Runic::SimulationPortOutbox of durable operations with stable IDs and an inbox of results drained at safe ticks. The Engine's only door to persistence; it knows no service, SQL or protocol.
Persistence bridgeRunicGame · RunicGame::Server (Source/Server/Persistence)Decides what is durable: builds EnterWorld, GrantLoot, Checkpoint and the other operations from Flecs state, and applies their results. The Game's only C++ that knows durable state exists.
ServicesBridgeLayerRunicPlatform · server bindings (PBND-1, PBND-4)Implements the service port: asynchronous gRPC calls and NATS publish and subscribe on I/O threads, completions queued for safe ticks. The only C++ that holds network clients to services.
Snapshot contributorsRunicEngine · DistributedSimulation (DSIM-3)Handoff between simulations moves state simulation to simulation, never through the database.

A session, end to end

sequenceDiagram

  participant A as Accounts
  participant S as Simulation (C++)
  participant B as ServicesBridge (C++)
  participant G as Go services
  participant P as PostgreSQL
  C->>A: login
  A->>P: account, entitlements
  A-->>C: signed connect ticket
  C->>S: connect with the ticket (checked locally)
  S->>B: EnterWorld ops in the outbox
  B->>G: parallel gRPC: Character.Load, Inventory.Load, Quest.LoadActive
  G->>P: reads in each service's own schema
  G-->>B: results
  B-->>S: inbox, applied at one safe tick: the character spawns
  Note over S: the tick never waits for I/O
  S->>B: GrantLoot with an op ID
  B->>G: Inventory.GrantLoot
  G->>P: ledger op + idempotency key, one transaction
  S-)B: quest, kill and map facts
  B-)G: NATS JetStream to Quest, Character, Rankings
  S->>B: checkpoint batch (about every 60 s)
  B->>G: Character.Checkpoint
  C->>S: logout
  S->>B: final checkpoint, then the entity is removed
